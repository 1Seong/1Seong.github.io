# portfolio-design-review — 한눈에 보기 리뷰 (보고 위주)

## 1. 촬영과 지표

```bash
node .claude/scripts/check-portfolio.mjs --render            # 데스크톱 + 지표
node .claude/scripts/check-portfolio.mjs --render --mobile   # 모바일 + 지표
node .claude/scripts/shot.mjs --label=review --page=all      # 첫 화면 + 섹션별 (데스크톱)
node .claude/scripts/shot.mjs --label=review --page=all --mobile
```

- 스크린샷은 `<TMP>/portfolio-shots/review/`에 있다(`<TMP>`는 `CLAUDE.md`의 검증 절 참고). `*-fold*.png`(첫 화면)부터 본다.
- 지표 중 **홈 길이, Projects 시작 위치, 상세 Overview 시작 위치**를 기록하고, 이전 리뷰 값이 있으면 비교한다.
- 외부 호스트 로드 실패는 샌드박스 제한일 수 있다. 다만 그 리소스가 없을 때 화면이 어떻게 보이는지는 실제 위험이므로 같이 적는다.

## 2. 점검 기준

각 항목을 화면에서 직접 확인한다. 추측으로 채우지 않는다.

**A. 첫 화면 (5초 테스트)**
- 홈 첫 화면만 보고 이 사람의 직무, 대표 성과, 대표 프로젝트를 말할 수 있는가
- 상세 첫 화면만 보고 프로젝트가 무엇이고 본인이 무엇을 했는지 알 수 있는가 (검은 영상, 빈 영역만 있지 않은가)

**B. 정보 위계와 스캔 동선**
- 제목 → 핵심 한 줄 → 근거 순으로 시선이 흐르는가
- 중요한 정보(프로젝트, 역할, 성과)가 덜 중요한 정보(장식, 긴 목록)보다 먼저 나오는가
- 스크롤 연동 효과(흐림, 축소)가 읽기를 방해하지 않는가

**C. 밀도와 길이**
- 카드와 섹션의 여백이 비교를 방해할 만큼 크지 않은가
- 콘텐츠 길이 가정(`goal` 20~30자, `solution` 2개 × 40~85자, troubleshooting 20~40자)보다 긴 텍스트에서도 깨지지 않는가

**D. 일관성**
- 같은 종류의 카드가 같은 높이·구조·버튼을 가지는가 (빠진 버튼, 빈 상자, 엇갈린 행)
- CSS 변수(`--gold` 등)와 기존 컴포넌트 클래스를 벗어난 값이 있는가

**E. 반응형**
- 390px에서 줄바꿈, 넘침, 가로 스크롤이 없는가
- 모바일에서 목차, 영상, 그리드가 본문을 과하게 밀어내지 않는가

**F. 접근성 (자세히는 `design:accessibility-review`)**
- 본문과 보조 텍스트 대비 4.5:1 이상 (특히 `--cream-3`가 진한 배경 위에 올라갈 때)
- 아이콘만 있는 버튼에 텍스트 라벨이나 `aria-label`이 있는가
- 키보드로 카드, 슬라이더, 목차를 조작할 수 있는가

## 3. 보고

세 등급으로 묶는다. 각 항목에는 근거 스크린샷 파일명과 `index.html:줄`, 제안 수정안을 붙인다.

1. 🔴 한눈에 보기를 직접 막는 것
2. 🟡 정돈과 일관성
3. 🟢 사소한 것

- 잘 된 점도 짧게 적는다. 바꾸지 말아야 할 것을 알려 주는 역할이다.
- 내용(문구, 링크, 미디어) 수정이 필요하면 `design.md`의 `[내용 요청]` 메모 형식으로 따로 적는다.
- 개선 작업은 한 번에 하나씩 제안하고, 사용자가 고른 것만 진행한다.
